# 무료 한도 재확인 절차

목표: 설계서 §10의 모든 수치가 **공식 페이지 원문**과 일치하는지 확인하고, 수치·페이지 갱신일·열람일·출처 URL을 `docs/limits-check.md`에 남긴다. 기억이나 제3자 요약으로 채우지 않는다.

## 1. 대상 목록 만들기

설계서 §10.1·§10.2·§10.3 표와 하단 Sources의 URL을 모두 뽑는다. 그 밖에 반드시 확인할 항목:

- Workers Static Assets 요청이 Worker 요청 한도에 집계되는지 — Cloudflare 공식 문서(Static Assets 과금/한도 페이지)에서 확인. 제3자(flarecalc)만 있는 상태를 해소한다.
- GitHub Actions 공개 저장소 표준 러너 무료 조건 — GitHub 공식 문서(Actions billing / usage limits).
- 설계서 §11 버전(Hono·Vite·Wrangler·Node LTS)은 한도가 아니므로 여기서 다루지 않는다.

## 2. 각 URL 열기

- `WebFetch`로 공식 페이지를 연다. 프롬프트에 "무료 플랜 수치와 페이지의 last updated 날짜를 원문 그대로 인용"을 요구한다.
- 페이지가 로그인·콘솔 전용이거나 JS 렌더라 수치를 못 읽으면 **추정하지 않는다** → "사람 작업"으로 남긴다.
- 리다이렉트되면 최종 URL을 기록한다.
- 수치가 설계서와 다르면 표에 "변경"으로 표시하고 이전 값·새 값을 함께 적는다.

## 3. `docs/limits-check.md` 형식

```markdown
# 무료 한도 재확인 (설계서 §10)

- 확인일: YYYY-MM-DD (열람자: Claude Code / 운영자)
- 상태 범례: 확인 = 공식 원문에서 수치 일치 · 변경 = 공식 원문이 설계서와 다름 · 미확인 = 공식 원문으로 확인 못 함(사람 작업)

| # | 서비스 | 항목 | 설계서 §10 값 | 공식 원문 값(인용) | 상태 | 페이지 갱신일 | 출처 URL |
|---|---|---|---|---|---|---|---|

## 사람 작업
- [ ] <항목> — 왜 사람이 해야 하는지, 캡처 저장 경로 `docs/evidence/captures/…`

## 설계서 반영
- 변경된 값과 설계서 반영 여부(커밋)
```

"미확인" 상태는 사람 작업 체크박스와 1:1로 대응해야 한다. 미확인 항목이 사람 작업 목록 밖에 있으면 완료가 아니다.

## 4. 설계서 반영

- 값이 바뀌었으면 설계서 §10 표를 먼저 고치고(CLAUDE.md: 설계서 먼저), §6.2 예산 근거에 영향이 있으면 같이 표시한다. 예산 수치 자체를 바꿔야 하면 §14.1-2/3에 해당하므로 `docs/DECISIONS.md`에 적고 사용자에게 묻는다.
- §10 제목의 확인일과 머리말 변경 이력에 한 줄 추가(`docs:` 커밋).
- 제3자 출처만 있던 항목이 공식 확인되면 출처 열에서 제3자 표기를 공식 URL로 바꾼다.
