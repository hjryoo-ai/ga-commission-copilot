# Phase 작업 절차

정본은 `docs/GA수수료설명코파일럿_설계서.md`, 작업 지시는 `docs/PHASES.md`, 규약은 `CLAUDE.md`(절대 규약 10개)다.

## 1. 시작 전

1. `CLAUDE.md` 절대 규약 10개를 다시 읽는다.
2. `docs/PHASES.md`에서 **현재 Phase 블록만** 읽는다. 블록이 참조하는 설계서 섹션(§)과 상위 설계서 섹션을 연다.
   - 상위 설계서: `../ga-agent-portal/docs/설계서.md`. CLAUDE.md는 v1.1이라고 하지만 실제 파일 버전은 머리말에서 확인하고, 버전 차이는 증거 문서의 "남은 이슈"에 적는다.
3. 지시 범위를 목록으로 만든다. 다음 Phase의 파일·코드는 만들지 않는다(빈 디렉터리 골격은 지시에 있을 때만).

## 2. 불일치·미결정 처리

| 상황 | 처리 |
|---|---|
| 설계서 §14.1 미결정 항목에 닿음 | 임의로 정하지 않는다. `docs/DECISIONS.md` 표에 `일자 · 항목(§14.1-N) · 선택지 · 근거` 행을 추가하고 사용자에게 질문한 뒤 그 부분은 멈춘다 |
| PHASES 지시와 설계서가 다름(개수·이름·버전 등) | 설계서가 정본이다. 설계서를 따르고, 지시 쪽 오류는 증거 문서 "남은 이슈"에 적고 사용자에게 알린다 |
| 설계서 자체를 고쳐야 함 | 설계서를 **먼저** 고친다(같은 커밋). 머리말 변경 이력에 한 줄 추가, 커밋 접두어 `docs:` |
| 외부 서비스 추가 | 설계서 §10에 공식 출처 URL·한도를 먼저 적는다(CLAUDE.md 규약 6) |
| 유료 플랜 전용 기능이 필요해 보임 | 쓰지 않는다. 대안을 찾거나 질문한다 |

## 3. 버전 고정

설계서 §11: 구현 시점에 `npm view <pkg> version`으로 확인하고 `package.json`에 정확한 버전으로 고정한다(`^` 없이). 설계서가 정한 메이저·마이너 라인(예: Vite 8.1, Hono 4.13.x)이 최신과 다르면 설계서 라인 안의 최신 패치를 쓰고, 선택 근거를 증거 문서에 적는다. 피어 의존성 충돌은 `npm view <pkg>@<ver> peerDependencies`로 확인한다.

## 4. 증거 문서 `docs/evidence/phase-N.md`

증거 없는 완료 선언은 하지 않는다. 출력은 **실제로 돌린 결과만** 붙인다. 돌리지 못한 단계는 "미실행"과 이유를 적는다.

긴 로그 원문은 `docs/evidence/logs/phase-N-<단계>.log`에 저장하고, 본문에는 요약과 경로를 남긴다. 캡처는 `docs/evidence/captures/phase-N-<이름>.png`에 둔다.

템플릿:

```markdown
# Phase N — <제목> 증거

- 수행일: YYYY-MM-DD
- 기준 문서: 설계서 v0.x §…, PHASES.md Phase N
- 도구 버전: node …, pnpm …, wrangler …, java …

## 완료 기준 대조

| # | 완료 기준(PHASES.md 원문) | 결과 | 증거 |
|---|---|---|---|
| 1 | … | 통과 / 실패 / 사람 작업 대기 | 아래 §… / 로그 경로 |

## 실행 명령과 출력

### <단계 이름>
​```bash
$ <명령>
​```
​```
<출력 요약 — 마지막 수십 줄 또는 핵심 줄>
​```
전체 로그: `docs/evidence/logs/phase-N-<단계>.log`

## 산출물

- 파일 목록(주요 경로) 한 줄씩

## 결정·편차

- 지시와 다르게 한 것, 이유

## 사람 작업

- [ ] <사람만 할 수 있는 일 — 콘솔 캡처, 로그인, 시크릿 등록 등> — 담당: 운영자

## 남은 이슈

- …
```

로그를 저장할 때는 `<명령> 2>&1 | tee docs/evidence/logs/phase-N-<단계>.log`처럼 실제 출력을 남긴다. ANSI 색 코드가 섞이면 `NO_COLOR=1`이나 `--color=false`로 다시 돌린다.

## 5. 완료 체크리스트

- [ ] PHASES 블록의 번호 항목 전부에 산출물이 있다
- [ ] 완료 기준 각 줄이 증거 표에 있고, 상태가 정직하다(사람 작업 대기 = 미완료로 표기)
- [ ] `pnpm -r test` 전체 출력이 로그로 남아 있다
- [ ] 시크릿·`.dev.vars`가 저장소에 없다(`.dev.vars.example`만)
- [ ] 설계서를 고쳤다면 변경 이력 행이 있다
- [ ] 다음 Phase 코드를 만들지 않았다
- [ ] 사용자에게 보고할 때 사람 작업·미실행 단계를 먼저 말한다
